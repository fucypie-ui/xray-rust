## Completion and maintenance rules

A row closes only when (1) native input reaches the real implementation, (2) required output/state/error/wire behavior matches pinned Go, (3) independent fixtures exist where deterministic, (4) live Go/Rust testing covers each applicable direction and malformed/unauthenticated cases, and (5) lifecycle/platform/feature-flag gates pass on the integrated revision. Pure CLI/config rows use independent process/output/accept-reject tests rather than meaningless socket-session gates. Randomized output is compared semantically where exact bytes are intentionally random.

A helper or new dependency never closes a runtime row by itself. Removed/unregistered surfaces remain outside the feature target but their observable rejection is tested. No blanket claim is made for an uninspected platform or a future Go commit. Platform-supported sockets, TUN and kernel/userspace differences require OS-matrix results; unsupported Go build branches need matching behavior, not fabricated support.

This matrix is exhaustive over the default-distribution registration edges, native declared config-field ownership, registered protobuf methods and supported CLI leaves enumerated above. Behavioral rows group related subfeatures; the field census is the closure checklist for that granularity, not a claim that every possible input combination was tested. The integration lane must maintain the selector/field/RPC/CLI census when the Go pin changes and split rows whenever one grouped behavior is promoted independently.
