## Interfaces to settle before integration

1. **Configured runtime contract:** typed protocol settings, common transport/security/mask selection, inbound stream/datagram factory, outbound stream/datagram connection and shared DNS/routing/policy/stats context. Preserve all Go address/network/user/tag metadata.
2. **Lifetime contract:** instance-owned cancellation and task handles for listeners, sessions, UDP pumps, timers, IP stacks, QUIC connections, observers and API services; close drains where required and completes before ports/system state are reused. Never detach tasks as an accidental success path.
3. **Packet contract:** UDP/IP operations retain packet boundaries, destination/source context and maximum sizes; a generic byte stream must use an explicit framing adapter rather than losing datagrams. WireGuard operates on authenticated IP packets before TCP/UDP dispatch.
4. **Handshake contract:** TLS/REALITY owns certificate/hello authentication; wrappers expose the authenticated SNI/ALPN/state needed by Vision/fallback/routing without spoofing successful validation. Generic wrappers are applied once and in Go-equivalent order.
5. **Mutable app contract:** runtime inbound/outbound/user/rule changes affect the exact handlers/route state used by dispatcher; RPC libraries cannot mutate shadow in-memory copies while the executable keeps stale state.
6. **Evidence contract:** every fixture/log includes capability ID, target Go pin, generator/test revision, Rust tested revision, dependency lock identity, role/direction/options, expected result and SHA256 where deterministic. Disclose skips and unavailable OS capabilities explicitly.

No new architecture is mandated where the current code already satisfies these boundaries. Prefer the narrowest adapter around a maintained engine and existing dispatcher instead of a second independent runtime that drifts from config/lifecycle semantics.
